# Exam Grader — Техническая спецификация v1

> [English version](SPEC_EN.md)

## **1. Обзор**

Автоматизированная система распознавания рукописных экзаменационных бланков и проверки ответов по предоставленному ключу. Система обрабатывает отсканированные PDF-формы через пайплайны компьютерного зрения и машинного обучения, формируя Excel-отчёты с оценками.

### **Ключевые цели**

- Автоматизировать трудоёмкий процесс ручной проверки экзаменов.
- Предоставить **два бэкенда распознавания**: локальная модель CLIP (офлайн) и OpenAI Vision API (облако).
- Генерировать подробные Excel-отчёты со встроенными превью ячеек для верификации.
- Поддерживать поля замены — студенты могут исправить свои ответы.

### **Философия проекта**

- Архитектура с одним пакетом — достаточно простая для понимания и быстрого развёртывания.
- Ленивая загрузка моделей — ML-модели загружаются при первом использовании, а не при импорте.
- Конфигурация через константы — все пороги, пути и веса оценок в одном файле.
- Чёткое разделение ответственности — models, recognition, processing, grading и export — независимые модули.

## **2. Архитектура**

### **2.1 Архитектура с одним пакетом**

```
exam_grader/
├── config.py           # Константы конфигурации
├── models/             # Структуры данных предметной области
├── recognition/        # Пайплайн распознавания
├── processing/         # Утилиты обработки изображений
├── grading/            # Проверка ответов и начисление баллов
└── export/             # Генерация Excel-результатов
```

### **2.2 Ответственности модулей**

| Модуль | Назначение | Импортирует из |
|--------|---------|-------------|
| `config` | Константы, пути, пороги | только stdlib |
| `models` | Классы Form, Row, Cell, Symbol | `config`, `processing`, `recognition` |
| `processing` | Выравнивание, стилизация, конвертация PDF | `config` |
| `recognition` | Распознавание CLIP и OpenAI, оркестрация | `config`, `models` |
| `grading` | Сравнение ответов, расчёт баллов | `config` |
| `export` | Генерация Excel со встроенными изображениями | `config`, `models` |

### **2.3 Поток данных**

Два пути распознавания используют общий пайплайн проверки и экспорта:

```
                                  ┌─── Режим CLIP ─────────────────────┐
                                  │  Стилизация → OCR по ячейкам →     │
Загрузка PDF → Изображения → Выравн.─┤  Пустые/Минусы/Запятые          ├→ Проверка → Excel
                                  │                                    │
                                  ├─── Режим OpenAI ───────────────────┤
                                  │  Отправка → gpt-5.2 → Парсинг JSON  │
                                  └────────────────────────────────────┘
```

## **3. Стек технологий**

| Категория | Технология | Назначение |
|----------|-----------|---------|
| Язык | Python 3.10+ | Современные type hints, f-strings |

| Валидация | Pydantic | Валидация моделей данных |

## **5. Спецификации модулей**

### **5.1 Конфигурация (`config.py`)**

Центральное хранилище всех констант. Без рантайм-состояния.

**Константы путей:**
- `TEMPLATE_PATH` — эталонное изображение формы для выравнивания
- `CELL_COORDS_PATH` — JSON-файл с координатами ячеек
- `REF_PICS_DIR` — директория с эталонными изображениями цифр
- `SAVED_EXCELS_DIR` — директория для сохранённых результатов

**Пороги обработки:**
- `PDF_ZOOM` (6.0) — коэффициент масштабирования PDF (~432 DPI)
- `EMPTY_CELL_THRESHOLD` (0.01) — соотношение объёма пикселей, ниже которого ячейка считается пустой
- `SYMBOL_MIN_HEIGHT_RATIO` (0.4) — минимальная высота символа относительно высоты ячейки

**Бизнес-правила:**
- `SCORING_WEIGHTS` — баллы за задание (З1: 0,5; З2-9: 1,0; З10: 1,5)
- `NUM_QUESTIONS` (10) — количество заданий на форме
- `CELLS_PER_ROW` — количество ячеек ввода в строке

**Конфигурация ML:**
- `CLIP_VISION_MODEL_NAME` — идентификатор fine-tuned модели CLIP
- `CLIP_INPUT_SIZE` (128) — размер изображения для входа CLIP

### **5.2 Модели (`models/`)**

**Иерархия классов:**

```
Form
 ├── rows: dict[str, Row]     # 23 строки всего
 │    ├── "date"               # 8 ячеек
 │    ├── "user_id"            # 8 ячеек
 │    ├── "version"            # 4 ячейки
 │    ├── "answer1"..."answer10"     # 9 ячеек каждая
 │    └── "correction1"..."correction10"  # 9 ячеек каждая
 │
 Row
 ├── cells: list[Cell]
 ├── user_answers: list[str | None]
 ├── correct_answers: list[str]
 └── row_image: np.ndarray | None
 │
 Cell
 ├── x, y, w, h: int | None     # Координаты на выровненном изображении
 ├── user_value: str | None      # Распознанное значение
 └── correct_value: str | None   # Ожидаемое значение
```

**Ключевое проектное решение:** строки хранятся в `dict[str, Row]` с ключами по имени (например, `form.rows["answer3"]`) вместо динамических атрибутов. Это типобезопасно, итерируемо и избегает `setattr`/`getattr`.

### **5.3 Распознавание (`recognition/`)**

**`FormRecognition.run_pipeline(mode, api_key, openai_model)`** поддерживает два режима:

**Режим CLIP (`mode="clip"`, по умолчанию):**

1. Загрузка координат ячеек из JSON
2. Загрузка отсканированного изображения и шаблона
3. Выравнивание изображения по шаблону (SIFT + гомография)
4. Стилизация изображения (белые границы, инверсия, центрирование символов)
5. Загрузка правильных ответов из DataFrame
6. Запуск OCR-пайплайна (распознавание цифр, обнаружение пустых ячеек, спецсимволов)
7. Генерация превью-изображений строк

**Режим OpenAI (`mode="openai"`):**

1. Загрузка координат, изображения и шаблона (аналогично CLIP)
2. Выравнивание изображения по шаблону
3. Загрузка правильных ответов
4. Отправка полного выровненного изображения страницы в OpenAI Vision API (gpt-5.2)
5. Парсинг структурированного JSON-ответа и заполнение `Form` через `set_answers_from_dict()`
6. Генерация превью-изображений строк

Последующий пайплайн проверки и экспорта идентичен для обоих режимов.

**`DigitClassifier`** (только режим CLIP) использует ленивую загрузку:
- Модели не загружаются при импорте
- Первый вызов `predict()` инициирует загрузку модели
- Использует CLIP ViT-B/32, дообученную на MNIST
- Сравнивает эмбеддинг изображения ячейки с 10 предвычисленными эталонными эмбеддингами
- Возвращает метку цифры с наибольшим косинусным сходством

**`openai_recognizer`** (только режим OpenAI):
- Кодирует изображение страницы в base64 и отправляет в gpt-5.2 со структурированным промптом
- Ожидает JSON-ответ с ключами: `date`, `user_id`, `version`, `answer_1`–`answer_10`, `correction_1`–`correction_10`
- Нормализует ответ к внутренним именам строк (например, `answer_1` → `answer1`, убирает точки из дат)
- Импортирует пакет `openai` лениво — он нужен только при выборе режима OpenAI

### **5.4 Обработка (`processing/`)**

**Пайплайн выравнивания:**
1. Обнаружение признаков SIFT на шаблоне и отсканированном изображении
2. Brute-force сопоставление с перекрёстной проверкой
3. Оценка гомографии через RANSAC
4. Перспективное преобразование для выравнивания сканированного изображения по координатам шаблона

**Пайплайн стилизации изображения:**
1. Рисование белых границ вокруг ячеек для изоляции содержимого
2. Инверсия изображения (белое на чёрном для поиска контуров)
3. Для каждой ячейки: поиск контура символа, масштабирование для заполнения ячейки, центрирование

### **5.5 Проверка (`grading/`)**

**Логика проверки ответов:**
- Задание считается правильным, если `правильный_ответ == ответ_студента` ИЛИ `правильный_ответ == замена_студента`
- Ответы нормализуются: запятые заменяются на точки, конвертируются во float и обратно в строку
- Финальный вывод заменяет оригинальные ответы на замены, где замены существуют

### **5.6 Экспорт (`export/`)**

**Excel-вывод включает:**
- Дату, код участника, вариант
- Ответы по каждому заданию с превью-изображениями ячеек
- Баллы по каждому заданию и общий балл (как формула SUM в Excel)

## **6. Управление конфигурацией**

Вся конфигурация находится в `exam_grader/config.py`. Нет переменных окружения, нет `.env`-файлов — приложение предназначено для локальной однопользовательской работы.

**Разрешение путей:** все пути вычисляются относительно расположения `config.py` с помощью `pathlib.Path`, что делает пакет переносимым.

## **8. Паттерны проектирования и соглашения**

### **8.1 Ленивая загрузка**

Тяжёлые ML-модели и опциональные зависимости загружаются по требованию:

- **Модель CLIP** — обёрнута в класс `DigitClassifier` с удобной функцией на уровне модуля. Модели загружаются при первом вызове `predict()`.
- **Клиент OpenAI** — пакет `openai` импортируется внутри `recognize_form_with_openai()`, поэтому он нужен только при выборе режима OpenAI.

```python
_classifier: DigitClassifier | None = None

def predict_digit(image: np.ndarray) -> tuple[str, np.ndarray]:
    global _classifier
    if _classifier is None:
        _classifier = DigitClassifier()
    return _classifier.predict(image)
```

### **8.2 Аннотации типов**

Все публичные функции и атрибуты классов имеют аннотации типов. `from __future__ import annotations` используется для прямых ссылок и синтаксиса `X | Y` на Python 3.10+.

### **8.3 Стиль кода**

- **Именование:** `snake_case` для функций/переменных, `PascalCase` для классов
- **Константы:** `UPPER_SNAKE_CASE` в `config.py`
- **Комментарии:** только на английском, объясняют только неочевидные намерения
- **Строки документации:** присутствуют на всех публичных классах и функциях
- **Длина строки:** 100 символов (настроено в `pyproject.toml`)
- **Импорты:** отсортированы по правилам isort (через Ruff)

### **8.4 Границы модулей**

```
config         ← только stdlib
processing     ← config, внешние библиотеки
recognition    ← config, models, processing
models         ← config, processing, recognition
grading        ← config, внешние библиотеки
export         ← config, models
```

Функциональные модули (`grading`, `export`) не импортируют друг друга.
